# Earthsonic — Step 36 Scientific Jukebox

This upgrade adds a NASA POWER scientific playback panel inside the existing Jukebox. It uses the already implemented `GET /api/science/climate` endpoint; it does not change the FastAPI backend, station dataset mapping, saved mixes schema, or existing Science Labs.

## Scope

- Loads NASA POWER `T2M`, `RH2M`, and `WS2M` daily gridded meteorological values at explicitly chosen coordinates and UTC dates (up to 31 days).
- Adds synchronized Web Audio playback, with the visible date driven by the AudioContext clock.
- Provides independent temperature, humidity, and wind volume/mute controls and one master science volume.
- Supports play/pause, per-day seek, skip and reset.
- Pauses station playback when scientific audio starts; stops scientific audio when station playback, station switching, or saved-mix loading starts.
- Omits missing layers, preserves NASA numeric readings, and links to the original NASA API source.
- Labels science playback as independent from the currently selected NASA SVS video station.
- Does not yet support saving scientific layer mixes to the old station-only Saved Mixes schema.

## Browser acceptance test

Start both backend and frontend, open a Jukebox station, load NASA data, click Play NASA data, and verify the active date advances day-by-day. While playing, change all three layer volumes, mute/unmute wind, seek forward, pause, and resume. Click the original station's Play control and verify science playback stops. Switch stations and verify science audio stops again. Test loading a saved station mix and ensure original station mixing remains intact. Try an invalid date span and confirm an error without fake fallback data.

## Limitations

This is not evidence that each SVS visualization has its own calibrated underlying scientific dataset. NASA POWER data are gridded analysis/reanalysis values for the chosen coordinate and date range, and the musical pitches are generated by Earthsonic, not recorded by NASA. The sound scheduler is unit tested offline, but browser audio and live API behavior require local acceptance testing. The existing saved-mix storage holds station settings only, not science layer settings.
